## GPUI uniform_list 间距坑（2026-08-25）
- 列表项之间加间距：**`margin`（`mb`）在 `uniform_list` 里无效**——它按"索引 × 测量高度"绝对定位子项，
  margin 被忽略，导致相邻选中行底色贴在一起。
- 正确做法：间距必须做进元素高度里。本做法：每个列表项仍是单层卡片 `h(56)`，在 processor 渲染循环里
  统一用外层 `div().h(px(62.0)).child(card)` 包一层，底部 6px 即实打实的空隙（卡片 56 + 外壳 62）。
  不要在每个 match 分支里手动嵌套 `child(div()...)`，容易数错括号编译不过；把 62 外壳放在 processor 一处即可。

## 修复：gpui_component 的 Input 导致启动闪退（Root::read unwrap None）

- 现象：加搜索框（gpui_component `Input`）后程序启动即 panic，
  `gpui-component-0.5.1/src/root.rs:268:14` 的 `.unwrap()` 对 `None`，
  退出码 `0xc0000409` (STATUS_STACK_BUFFER_OVERRUN)。
- 根因：`main()` 里 `open_window` 直接用 `MusicPlayer` 当窗口根视图。
  `Input` 等 gpui_component 控件在渲染时调用 `Root::read(window, cx)`，
  内部是 `window.root::<Root>().expect(...).unwrap()`。当窗口根不是 `Root` 类型时，
  `window.root::<Root>()` 返回 `Some(None)`，`.unwrap()` 直接 panic。
  （之前没用 Input 等控件所以从不触发，加了搜索框才暴露。）
- 修法：主视图必须用 `gpui_component::Root` 包一层：
  ```
  |window, cx| {
      let main_view = cx.new(|cx| MusicPlayer::new(cx));
      cx.new(|cx| Root::new(main_view, window, cx))
  }
  ```
  `Root::render` 会正常渲染内部 `view`（root.rs:411 `.child(self.view.clone())`），界面不丢。
- 结论（重要复用经验）：**只要用了 gpui_component 的 `Input` / 通知 / 弹窗 / 右键菜单等
  依赖 Root 上下文的控件，窗口根视图就必须是 `gpui_component::Root`**，否则渲染即 panic。
- 提交：7d419c7 fix: 主视图用 Root 包裹

## 扫描诊断：scan_dir 加跳过日志（定位"少了歌"）

- 用户反馈部分歌曲没被扫到。扫描条件（`audio.rs::scan_dir`）：
  - 全递归遍历（含隐藏文件夹，不跳过）；
  - 扩展名白名单 `AUDIO_EXTENSIONS = [mp3,flac,wav,ogg,aac,m4a]`；
  - `read_meta`（lofty）必须成功，否则静默丢弃。
- 关键坑：**`load_music_folder` 命中 `settings.json` 的 `cached_folders` 就直接读缓存 `return`，启动不重扫磁盘** → 加的新歌不出现，需点设置面板里文件夹的「刷新」按钮或清缓存。
- 改动（f0e24d5）：`scan_dir` 增加 stderr 诊断：
  - 白名单扩展名但 `read_meta` 失败 → `[扫描] read_meta 失败，已跳过: <path>`
  - 疑似音频扩展名（opus/wma/ape/m4b/mid/aiff/dsf/tta/tak/wv/alac/caf/amr）但不在白名单 → `[扫描] 扩展名未支持（疑似音频，已跳过）`
  - 普通非音频文件不打，避免刷屏；扫描结束打印 `[扫描] 完成：命中 N 首`
- 注意：要看日志必须真正触发扫描（刷新按钮 / 清缓存后启动），缓存命中时 scan_dir 不调用、无日志。

## 实测修正：MINI姐 那批 MP3 是 lofty 整文件解析失败（走兜底），不是"三件套缺失"

- 之前基于字节分析推测"ID3v2.3 帧结构自洽、文件没坏、lofty 应能解析、只是缺 TIT2/TPE1/TALB 三件套"，
  但用户实跑日志明确打印 `[扫描] read_meta 退化兜底: C:\音频\MINI姐\...\21.妈妈的朋友 -mini姐.mp3`
  以及 `...\3.20更新\仙流1 -mini姐.mp3` —— **实测 lofty 0.21 对这批文件 `read()` 整体失败、返回 None、走兜底**。
- 结论：这类文件字节合法，但 lofty 对带 MP4 风格 TXXX 字段 / APIC 封面的 ID3v2.3 容错差，
  遇到它不认可的帧就整文件报错（不像 Windows 资源管理器能跳过坏帧继续读）。
  兜底层把标题回退成文件名，符合用户预期（"它就是显示兜底"）。
- 兜底代价：duration=0（时长显示 0:00）、歌手/专辑为空。后续若想让这类歌也显示真名/真时长，
  方向：① 手动解析 ID3 帧拿 TIT2/TIT3；② 播放时由 WinRT MediaPlayer 回填真标题/时长到列表。
  用户暂未要求，先保持现状。
