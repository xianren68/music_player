### SMTC 媒体会话修复（真实窗口句柄）
- **根因**：souvlaki 在 Windows 上用 `hwnd: null` 创建 `SystemMediaTransportControls`，无法关联窗口，导致音量弹出/锁屏/任务栏都不显示"正在播放"卡片（甚至 `MediaControls::new` 直接失败使 `media` 为 `None`）。
- **修复**：`MediaSession::new` 在 Windows 上改为接收真实 `HWND`；在 GPUI 的 `render(&mut self, w, cx)` 首次调用时（此时 `w: &mut Window` 可用）用 `w.window_handle()` 拿到 HWND 再创建会话。
- **关键类型转换**：raw-window-handle 0.6 的 `Win32WindowHandle.hwnd` 是 `NonZero<isize>`，需 `win32.hwnd.get() as *mut c_void` 转成 souvlaki 期望的 `Option<*mut c_void>`。
- **main.rs 改动**：`media_tx: Option<Sender>` 保存 channel 发送端供重建使用；`media_initialized: bool` 标志防止 render 中重复创建；`new()` 不再立即创建 media（只建 channel + 后台监听循环），推迟到窗口可用的 render。
- **依赖**：Cargo.toml 加 `raw-window-handle = "0.6"`。
- **验证日志**：运行时打印 `[media] SMTC 会话已用真实窗口句柄初始化` 即表示成功。
- **注意**：非 Windows 平台 `new()` 无 hwnd 参数，仍在 render 首次创建（MPRIS / MediaRemote）。

### SMTC 卡片仍不显示 → 封面 URL 构造错误（真正根因）
- **现象**：句柄初始化成功，但点播放仍不弹"正在播放"卡片。
- **根因**：souvlaki 0.8.3 Windows `set_metadata` 对 `cover_url` 做 `trim_start_matches("file://")` 后直接喂 `StorageFile::GetFileFromPathAsync`，要求 file:// 后紧跟**合法 Windows 绝对路径**。我们之前构造的是 `file:///C:/...`（三斜杠→残留前导 `/`）且 `canonicalize()` 带 `\\?\` 前缀 → 路径非法 → `set_metadata` 整体返回 Err → `display_updater.Update()` 不被调用 → 卡片不出现。当前播放歌曲 cover_path 通常为 Some，所以每次都命中坏分支。
- **修复**（media_session.rs `build_cover_url`）：canonicalize 后去掉 `\\?\`/`\\?\UNC\` 前缀，用 `file://` + 原始反斜杠绝对路径（两斜杠，不是三斜杠）。set_metadata 失败时打印错误并**去掉封面重试一次**，保证标题/歌手能弹卡片。set_playback 也加了错误日志。

### 音量弹出"正在播放"卡片（悬停系统托盘音量）不显示 → 改用 GetForWindow 绑定窗口 SMTC
- **现象**：任务栏缩略图控件(侧边栏悬停)能出现，但悬停音量图标的"正在播放"卡片不出现。
- **根因**：之前 Windows 用 `MediaPlayer.SystemMediaTransportControls()` 拿到的是**独立** SMTC（不绑定窗口）。任务栏缩略图按窗口显示，所以能出现；但音量弹出卡片是按"正在播放音频的窗口会话"关联的，独立 SMTC 不被提升为活跃媒体会话 → 不弹卡片。VLC/foobar2000 等驱动该卡片的标准做法是用 `ISystemMediaTransportControlsInterop::GetForWindow(hwnd)` 把 SMTC 绑定到真实窗口。
- **修复**（media_session.rs Windows imp）：用 `windows::core::factory::<SystemMediaTransportControls, ISystemMediaTransportControlsInterop>()` 拿互操作接口，再 `interop.GetForWindow::<SystemMediaTransportControls>(hwnd)`（泛型，直接返回带全部方法的**运行时类**）。`new()` 增加 `hwnd: *mut c_void` 参数；main.rs `get_window_hwnd(w)` 用 `HasWindowHandle::window_handle(w)` 显式取句柄（`Window` 自带同名固有方法返回 `AnyWindowHandle`，会遮蔽 trait 方法，必须显式调 trait）。
- **windows 0.61 API 关键坑**：
  - `ISystemMediaTransportControlsInterop` 在 `windows::Win32::System::WinRT`（非 `Win32::Media`），feature 需 `Win32_System_WinRT`。
  - `GetForWindow<T: Interface>` 返回 T，T 必须是运行时类 `SystemMediaTransportControls`（`ISystemMediaTransportControls` 是 COM 接口，无便捷方法）。
  - `HWND` 是 `struct HWND(pub *mut c_void)` 新类型，直接 `HWND(hwnd)` 包即可，不要 `as isize`。
  - raw-window-handle 0.6：`WindowHandle::as_raw()`（不是 `as_raw_handle()`）返回 `RawWindowHandle`。
- **状态**：已改为 GetForWindow 方式，音量弹出卡片✅已出现（用户确认）。但任务栏缩略图上的播放/暂停/上下首传输控件仍❌不出现。

### 任务栏缩略图传输控件缺失 → Windows 音频改走 WinRT MediaPlayer（2026-07-14 实施中）
- **已确认**：用 PowerShell 取 `Get-Process MainWindowHandle`(0xD12EC) == 代码里 `GetForWindow` 绑定的 hwnd(0xD12EC)，完全一致 → 绑定正确、窗口样式正常（`WS_EX_APPWINDOW`，非 TOOLWINDOW）。排除 hwnd/样式问题。
- **根因**：任务栏缩略图传输控件比音量卡片更严格——除 SMTC 启用外，还要求本窗口是"真正在播放媒体的应用"（音频会话类别=Media）。我们音频走 rodio/WASAPI 默认会话（非 Media 类别），所以 Windows 不把窗口识别为媒体应用，传输控件不渲染（移到缩略图上也只是放大页面，无按钮条）。
- **修复方案（已采用）**：Windows 平台 `Player` 改由 WinRT `MediaPlayer` 播放（音频会话自动 Media 类别 → 系统识别为媒体应用 → 任务栏传输控件必出）。保留 rodio 作为 OGG 等 Media Foundation 不支持格式的兜底（这些格式无任务栏控件但能出声）。
- **audio.rs 改造**：`mod imp` 按平台分实现；抽出共享 `RodioPlayer`（rodio::OutputStream/Sink）。Windows `Player{ media: Option<MediaPlayer>, rodio: Option<RodioPlayer>, using_rodio, volume }`。`play()` 中 ogg→rodio，否则 `MediaPlayer::new()` + 关闭其自带 SMTC(`SetIsEnabled(false)` 避免与 GetForWindow 的 SMTC 冲突) + `StorageFile::GetFileFromPathAsync`→`MediaSource::CreateFromStorageFile`→`mp.SetSource(&source)`+`SetVolume`+`Play()`；失败全兜底 rodio。`toggle/stop` 按 `using_rodio` 分流。进度条仍由 UI 计时器驱动（`current_progress()` 用 Instant），**不受影响**；seek 未实现，故只需 play/pause/resume/stop。
- **Cargo.toml**：windows 加 `Media_Core` + `Media_Playback`。
- **关键 API 坑（windows 0.61）**：`MediaPlayer::new()` 返回 `Result<MediaPlayer, Error>`（不是直接值）；`HSTRING` 在 `windows::core`（需在 imp 显式 `use windows::core::HSTRING`）；`MediaSource` 在 `windows::Media::Core`；`StorageFile::GetFileFromPathAsync(...).get()` 同步取结果（与 media_session 封面同模式）。**`SetSource` 直接传 `&MediaSource` 即可**——`MediaSource` 通过 `required_hierarchy!` 已实现 `IMediaPlaybackSource`，`SetSource<P0: Param<IMediaPlaybackSource>>` 接受它；**不要**用已删除的 `MediaPlaybackSource::CreateFromMediaSource`（0.61 无此函数，正确名是 `IMediaPlaybackSource::CreateFromMediaSource` 且 `IMediaPlaybackSource` 上也没有该方法）。
- **曲库格式实测（2026-07-14）**：`C:\Kugou` + `C:\音频` 共 1368 首，格式分布 MP3=1536、M4A=8、FLAC=2、WAV=1，**OGG=0**。→ rodio 兜底对当前曲库永不触发，但保留为防御性（日后加 OGG 仍可播，只是那首无任务栏控件）。结论：当前可放心走纯 MediaPlayer，混用 rodio 兜底无副作用。
- **media_session.rs 保持不变**（GetForWindow SMTC 已就绪，靠 MediaPlayer 音频会话激活传输控件）。
- **状态**：编译中，待用户验证任务栏缩略图传输控件是否出现。
